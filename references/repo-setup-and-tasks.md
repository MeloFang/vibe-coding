# 仓库初始化与任务流转

> 提炼自 mattpocock 的 `setup-matt-pocock-skills`（仓库初始化）和 `triage`（任务状态机）。
> 这两个技能原本绑在 issue tracker 上（WorkBuddy 没有 issue tracker），
> 但它们的有用内核可以脱离 tracker 落地：**初始化是一次性的本地配置，任务流转可以写在 `PLAN.md` 里**。

---

## 一、仓库初始化（每个项目跑一次）

> 完整流程见 `project-lifecycle.md` 第 ② 阶段「固定上下文」。这里是从 `setup` 抽出来的**一次性配置清单**。

### 初始化要问清三件事

跟用户确认，一次问完：

1. **任务追踪用什么？** GitHub Issues / GitLab Issues / 本地文件（`PLAN.md` 里的状态列）/ 其他。
2. **标签（labels）怎么分？** 任务状态用什么标签表达。
3. **文档放哪儿？** `docs/` 集中，还是散在代码目录旁边。

### 初始化检查清单

- [ ] `AGENTS.md` 已落盘（含构建/测试/风格命令）
- [ ] `GLOSSARY.md` 已建（哪怕只有几个核心词）
- [ ] `PLAN.md` 已建（含状态列）
- [ ] `.gitignore` 已配（构建产物、密钥、缓存）
- [ ] README 或 `HANDOFF.md` 有"怎么跑起来"
- [ ] 技术选型有 ADR 记录（为什么用这个框架而不是别的）

**为什么不放 issue tracker**：WorkBuddy 没有内置 tracker。用本地文件（`PLAN.md` 的状态列）同样能流转，而且**文档和代码同仓、一起进 git、可离线用**。需要远端协作再接 GitHub Issues，本地状态列作为镜像。

## 二、任务流转（状态机）

> 提炼自 `triage` 的核心思想：**任务不是一个静态列表，是一个状态机**。

### 状态定义

| 状态 | 标记 | 含义 | 进入条件 |
|:---|:---|:---|:---|
| **待规划** | ⬜ | 想法，还没拆成可执行步骤 | 进入 backlog |
| **已规划** | ⬜ | 已拆成步骤、有验收信号 | 规划阶段完成 |
| **进行中** | 🟡 | 正在做 | 前置步骤完成 |
| **阻塞** | ⛔ | 卡住，需要外部输入 | 发现阻塞 |
| **已完成** | ✅ | 做完且验证通过 | 验收信号通过 |
| **已放弃** | ⊘ | 决定不做 | 明确决定，记录原因 |

**关键**：`进行中` 只能有**一个**。同时标两个"进行中"意味着有人在抢活或者状态没维护。

### 流转规则

```
待规划 → 已规划 → 进行中 → 已完成
                      ↓
                    阻塞 → 进行中（解除后）
   任意状态 → 已放弃（记原因）
```

- **`阻塞` 必须写清卡在哪、需要什么**。只标"阻塞"不给解法，等于没标。
- **完成必须带验证信号**。"写完了"不算完成，"跑测试通过"才算。
- **放弃要记原因**。三个月后看到 ⊘ 会想"为什么不做"，原因写下来就不会重提。

### 每个任务该有的信息

```
| # | 任务 | 状态 | 依赖 | 验收信号 | 备注 |
|---|------|------|------|---------|------|
| 1 | <任务> | ✅ | 无 | <怎么验> | 完成于 <日期> |
| 2 | <任务> | 🟡 | 1 | <怎么验> | 卡在 <...> |
| 3 | <任务> | ⛔ | 2 | <怎么验> | 等 <谁> 提供 <什么> |
```

**没有"验收信号"列的任务不允许标为进行中**——那是"想做的事"，不是"可做的事"。

### 流转的节奏

- **每天/每步**：实现阶段每完成一步，更新状态 + `HANDOFF.md`。
- **每个阶段**：状态流转后更新阶段进度表。
- **发现新活**：先进"待规划"，不要插队直接开做——插队会让依赖关系失效。

## 和 issue tracker 的关系

需要远端协作时（多人、跨仓、公开项目），把 `PLAN.md` 的任务镜像到 GitHub Issues：

| 本地（真相源） | GitHub Issue 状态 |
|:---|:---|
| ⬜ 已规划 | Open |
| 🟡 进行中 | In Progress / assignee |
| ⛔ 阻塞 | Blocked（用 label 或 project field） |
| ✅ 已完成 | Closed |
| ⊘ 已放弃 | Closed + `wontfix` label |

**`PLAN.md` 是真相源**，Issue 是共享视图。冲突时以 `PLAN.md` 为准。
