# 子 Agent 驱动开发：多 Agent 协作实现

> 触发说法："用子 Agent 并行" / "dispatch 出去" / "这个任务可以拆分" / "多 Agent 协作" / "并行实现"

**铁律**：子 Agent 不是"甩锅"，是**用并行换时间 + 用审查保质量**。每个 dispatch 都必须带清晰验收标准。

---

## 两种模式对比

```
模式 A：subagent-driven-development（thorough，高质量）
每个任务 → 独立子 Agent → 审查 → 下一个任务

模式 B：executing-plans（cheapest，快速）
所有任务 → 单 Agent inline 执行 → 最终一次性审查
```

| 因素 | 模式 A（subagent） | 模式 B（executing） |
|------|-------------------|-------------------|
| **质量** | 高（每个任务都审查） | 中（最终一次性审查） |
| **速度** | 慢（审查开销） | 快（无中间审查） |
| **适用** | 重要功能 | 小功能 / 快速迭代 |
| **任务数** | 多（>5） | 少（<5） |
| **审查成本** | 可接受 | 不可接受 |

---

## 模式 A：subagent-driven-development

### 流程

```
① 拆分任务  →  ② Dispatch  →  ③ 实现  →  ④ 审查  →  ⑤ 下一个
```

| 步骤 | 产物 | 出口条件 |
|:---|:---|:---|
| ① **拆分任务** | 任务列表（每个 2-5 分钟） | 每个任务独立、可验证 |
| ② **Dispatch** | Dispatch 包（任务说明 + 验收标准） | 子 Agent 理解任务 |
| ③ **实现** | 代码 + 测试 | 红→绿循环完成 |
| ④ **审查** | 审查报告 | 严重问题已修复 |
| ⑤ **下一个** | 更新 PLAN.md 状态 | 状态已同步 |

### 步骤①：拆分任务

**原则**：
- 每个任务 **2-5 分钟**（不是 2-5 小时）
- 任务之间**无依赖**（可并行）
- 每个任务**独立可验证**

**输出格式**：
```markdown
## 任务拆分

**总任务**: <功能名称>

**子任务**:
1. <任务 1> —— 2 分钟，验收：<标准>
2. <任务 2> —— 3 分钟，验收：<标准>
3. <任务 3> —— 5 分钟，验收：<标准>
```

### 步骤②：Dispatch

**Dispatch 包格式**：
```markdown
## 任务 Dispatch

**任务**: <任务名称>

**验收标准**:
- <具体可验证标准 1>
- <具体可验证标准 2>
- <具体可验证标准 3>

**约束**:
- 不要改什么（如"不要动配置文件"）
- 必须用什么（如"必须用 GLOSSARY.md 定义的术语"）

**上下文**:
- 相关文件：<文件路径>
- 相关测试：<测试路径>

**截止时间**: <可选，如"10 分钟内">
```

**Dispatch 方式**：
- 新会话：开新会话，粘贴 Dispatch 包
- 子进程：如 Claude Code 的 `/agent` 命令
- 并行：多个子 Agent 同时执行不同任务

### 步骤③：实现

**子 Agent 职责**：
- 读 Dispatch 包，确认理解
- 走五步闭环（对齐→固定→规划→实现→复盘）
- 红→绿循环完成
- 提交代码 + 测试

**主 Agent 职责**：
- 等待子 Agent 完成
- 不干预实现细节
- 准备审查

### 步骤④：审查

**审查检查清单**：

**严重问题（blocking）**：
- [ ] 功能不符合 Dispatch 包
- [ ] 测试缺失
- [ ] 硬编码
- [ ] 安全漏洞
- [ ] 性能回退

**一般问题（non-blocking）**：
- [ ] 命名不一致
- [ ] 代码重复
- [ ] 注释缺失
- [ ] 格式问题

**审查输出格式**：
```markdown
## 审查报告

**任务**: <任务名称>

**严重问题**:
- [ ] 无
- [x] 测试缺失（turn 12, line 45）

**一般问题**:
- [x] 命名不一致（should use `user_id` not `uid`）

**决定**: <继续/修复后继续/停止>

**理由**: <为什么>
```

### 步骤⑤：下一个

**审查通过后**：
- [ ] PLAN.md 对应步骤标记为 done
- [ ] HANDOFF.md 更新进度
- [ ] Dispatch 下一个任务

**审查不通过**：
- [ ] 子 Agent 修复问题
- [ ] 重新审查
- [ ] 仍不通过 → 重新 Dispatch（换 Agent 或改任务说明）

## 模式 B：executing-plans

### 流程

```
① 读 PLAN.md  →  ② 顺序执行  →  ③ 最终审查
```

| 步骤 | 说明 |
|------|------|
| ① **读 PLAN.md** | 理解所有任务 + 验收标准 |
| ② **顺序执行** | 按 PLAN.md 顺序，一步一提交 |
| ③ **最终审查** | 所有任务完成后一次性审查 |

### 适用场景

- 小功能（<5 个任务）
- 快速迭代（时间压力高）
- 任务简单（无需复杂审查）

### 输出格式

```markdown
## 执行进度

**任务 1**: [x] 完成
**任务 2**: [x] 完成
**任务 3**: [ ] 进行中

**最终审查**:
- [ ] 所有任务完成
- [ ] 测试全绿
- [ ] 代码审查通过
```

---

## 选择标准

**用模式 A（subagent）**：
- ✅ 重要功能（核心逻辑）
- ✅ 任务多（>5 个）
- ✅ 审查成本可接受
- ✅ 时间压力低

**用模式 B（executing）**：
- ✅ 小功能（工具脚本）
- ✅ 任务少（<5 个）
- ✅ 审查成本高
- ✅ 时间压力高

---

## Dispatch 最佳实践

### ✅ 好的 Dispatch

```markdown
**任务**: 实现用户登录验证

**验收标准**:
- [ ] 输入正确用户名密码 → 返回 token
- [ ] 输入错误密码 → 返回 401
- [ ] 用户不存在 → 返回 404
- [ ] 密码为空 → 返回 400

**约束**:
- 不要改数据库 schema
- 必须用 GLOSSARY.md 定义的 `User` 术语
- 必须写测试（红→绿）

**上下文**:
- 相关文件：`src/auth.py`, `src/models/user.py`
- 相关测试：`tests/test_auth.py`
```

### ❌ 坏的 Dispatch

```markdown
**任务**: 做个登录功能

**验收标准**:
- 能登录就行

**约束**:
- 别搞砸了

**上下文**:
- 看着办
```

## 子 Agent 管理

### 子 Agent 类型

| 类型 | 职责 | 适用任务 |
|------|------|----------|
| **Coder** | 写代码 + 测试 | 功能实现 |
| **Tester** | 写测试 + 验证 | 测试覆盖 |
| **Reviewer** | 代码审查 | 质量把关 |
| **Researcher** | 调研方案 | 技术选型 |

### 子 Agent 配置

```markdown
**角色**: Coder

**背景**: 你有 3 年 Python 经验，擅长 FastAPI 和 SQLAlchemy

**任务**: <Dispatch 包>

**输出要求**:
- 代码必须有类型注解
- 测试必须覆盖所有边界
- 提交信息必须清晰
```

---

## 并行执行

### 并行策略

| 策略 | 说明 | 适用 |
|------|------|------|
| **完全并行** | 所有子 Agent 同时执行 | 任务无依赖 |
| **分批并行** | 每批 2-3 个 Agent | 部分依赖 |
| **串行** | 一个完成后下一个 | 强依赖 |

### 同步点

```
任务 1 ──┬──→ 审查 ──┐
任务 2 ──┼──→ 审查 ──┼→ 集成
任务 3 ──┴──→ 审查 ──┘
```

**同步点检查**：
- [ ] 所有子任务完成
- [ ] 所有审查通过
- [ ] 集成测试绿

## 常见错误

| 错误 | 症状 | 修复 |
|------|------|------|
| **Dispatch 不清晰** | 子 Agent 反复问问题 | 验收标准具体化 |
| **任务太大** | 超时 / 质量下降 | 拆分为 2-5 分钟 |
| **缺少审查** | 质量不可控 | 强制每个任务审查 |
| **并行过度** | 集成冲突 | 增加同步点 |
| **串行过度** | 速度慢 | 识别无依赖任务并行 |
