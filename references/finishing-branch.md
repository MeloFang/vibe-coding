# 分支收尾：完成一个功能后的决策流程

> 触发说法："这个功能做完了" / "任务完成了" / "测试全绿了" / "下一步呢" / "怎么收尾"

**铁律**：功能完成后**必须**走收尾流程，不许直接开始下一个功能。

---

## 决策流程

```
① 验证测试  →  ② 对照 PLAN.md  →  ③ 决定去向  →  ④ 清理现场
```

| 步骤 | 产物 | 出口条件 |
|:---|:---|:---|
| ① **验证测试** | 测试报告 | 全量测试绿 + 构建通过 |
| ② **对照 PLAN.md** | 验收记录 | 对应步骤标记完成 + 验收信号满足 |
| ③ **决定去向** | 决策记录 | 4 选项（Merge/PR/Keep/Discard）已选 |
| ④ **清理现场** | 清理记录 | worktree 已删除 / 分支已合并 |

---

## 步骤①：验证测试

**目标**：确认功能不仅"能跑"，而且"没破坏已有功能"。

### 验证清单

- [ ] **新功能测试绿**（针对本功能的测试全通过）
- [ ] **全量测试绿**（回归测试，确认没破坏已有功能）
- [ ] **构建通过**（编译/打包无报错）
- [ ] **性能达标**（如有约定性能指标）
- [ ] **无硬编码**（代码审查）
- [ ] **命名符合 GLOSSARY.md**（术语一致）

### 输出格式

```markdown
## 测试验证

**功能**: <功能名称>

**验证结果**:
- [x] 新功能测试绿（5/5）
- [x] 全量测试绿（128/128）
- [x] 构建通过
- [ ] 性能测试（不适用）

**备注**: <如有失败，记录失败测试和原因>
```

---

## 步骤②：对照 PLAN.md

**目标**：确认功能符合原始计划，不是"自己做嗨了"。

### 验证清单

- [ ] **对应步骤标记完成**（PLAN.md 里该步骤状态改为 done）
- [ ] **验收信号满足**（PLAN.md 里约定的验收标准已达成）
- [ ] **已知限制已记录**（未完成的部分记录到 HANDOFF.md）
- [ ] **无范围蔓延**（没做 PLAN.md 范围外的事）

### 输出格式

```markdown
## PLAN.md 对照

**对应步骤**: PLAN.md Step X

**验收信号**:
- [x] <验收信号 1>
- [x] <验收信号 2>

**已知限制**:
- <限制 1，如"仅支持单线程，多线程待后续">
- <限制 2>

**范围外事项**:
- <未做的功能，如"不支持批量导入">
```

---

## 步骤③：决定去向（4 选项）

**目标**：明确这个功能的最终去向，不许"悬空"。

### 4 选项对比

| 选项 | 适用场景 | 操作 | 示例 |
|------|----------|------|------|
| **Merge** | 主分支，小功能，无需审查 | 直接合并到 main | 修复 typo / 小优化 |
| **PR** | 重要功能，需审查，多人协作 | 创建 Pull Request，指定审查者 | 核心功能 / 架构变更 |
| **Keep** | 实验性功能，观察一段时间 | 保留分支，标记为 experimental | 新功能实验 / 备选方案 |
| **Discard** | 失败实验，技术验证 | 删除分支，记录教训到 HANDOFF.md | 走不通的技术路线 |

### 决策检查清单

- [ ] 选了 4 选项之一（不许"先放着"）
- [ ] 写了理由（为什么选这个）
- [ ] 如有后续，写了下一步

### 输出格式

```markdown
## 去向决定

**决定**: <Merge/PR/Keep/Discard>

**理由**:
- <为什么选这个，如"小功能，无需审查" / "核心功能，需审查" / "实验性，观察一段时间" / "走不通，记录教训">

**后续**:
- <如"已合并到 main" / "PR #123 已创建" / "标记为 experimental，观察 2 周" / "已删除，教训见 HANDOFF.md">
```

---

## 步骤④：清理现场

**目标**：不留尾巴，方便下次开发。

### 清理清单

| 去向 | 清理操作 |
|------|----------|
| **Merge** | - 已合并到 main<br>- 删除 feature 分支<br>- 删除 worktree（如有） |
| **PR** | - PR 已创建<br>- 指定审查者<br>- 保留分支直到 PR 合并 |
| **Keep** | - 分支标记为 experimental<br>- HANDOFF.md 记录观察期<br>- 保留 worktree（如有需要） |
| **Discard** | - 分支已删除<br>- HANDOFF.md 记录教训<br>- 删除 worktree |

### 输出格式

```markdown
## 清理现场

**清理操作**:
- [x] 已合并到 main / PR 已创建 / 分支已标记 / 分支已删除
- [x] worktree 已删除（如有）
- [x] HANDOFF.md 已更新

**备注**: <如有遗留问题>
```

## 何时使用

| 场景 | 触发时机 |
|------|----------|
| **功能完成** | 测试全绿，准备开始下一个功能前 |
| **任务完成** | PLAN.md 里某步骤标记完成时 |
| **实验结束** | 实验性功能观察期结束 |
| **分支合并** | 准备合并到 main 前 |

---

## 与其他流程的衔接

- **测试验证失败** → 走 `tdd-playbook.md` 诊断修复
- **发现架构问题** → 走 `architecture-review.md` 体检
- **需要重构** → 走 `deep-module-design.md` 设计
- **更新 HANDOFF.md** → 走 `handoff.md` 格式

---

## 常见错误

| 错误 | 症状 | 修复 |
|------|------|------|
| **直接开始下一个功能** | 没走收尾流程 | 强制：不许开始下一个，先收尾 |
| **悬空决定** | "先放着" / "再看看" | 强制：4 选 1，不许悬空 |
| **测试不全** | 只测新功能，不测回归 | 检查清单强制全量测试 |
| **范围蔓延** | 做了 PLAN.md 范围外的事 | 对照 PLAN.md 检查 |
| **未记录限制** | 已知限制没写 | HANDOFF.md 强制记录 |

```
    [ ] 性能达标（如有）

    [ ] 对应步骤标记完成
    [ ] 验收信号满足
    [ ] 已知限制已记录
    [ ] 无范围蔓延

[ ] ③ 去向决定
    [ ] 4 选 1（Merge/PR/Keep/Discard）
    [ ] 写了理由

    [ ] 分支已合并/PR 已创建/分支已删除

```

---

> **注意**：收尾不是"最后才做的事"，是**每个功能完成后必须做的事**。不许攒到最后一起收尾。
