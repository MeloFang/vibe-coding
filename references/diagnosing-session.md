# 会话诊断：当会话出问题时

> 触发说法："这会话不对劲" / "技能没触发" / "Agent 忽略了计划" / "重复工作" / "token 超支" / "查查这会话哪出了问题" / "诊断一下"

**铁律**：子 Agent 的发现是假设，不是事实。诊断时必须自己读会话记录，逐条核对。

---

## 诊断流程（4 阶段）

```
① 建立反馈环  →  ② 定位根因  →  ③ 给出修复  →  ④ 回归验证
```

| 阶段 | 产物 | 出口条件 |
|:---|:---|:---|
| ① **建立反馈环** | 会话时间线 + 预期 vs 实际对比 | 能复现问题，知道哪一步开始偏离 |
| ② **定位根因** | 根因分类（技能/Agent/流程） | 找到第一个异常点 + 原因 |
| ③ **给出修复** | 修复方案（改技能/重述计划/增检查点） | 方案可执行 |
| ④ **回归验证** | 验证记录 + HANDOFF.md 更新 | 新会话验证通过 |

---

## 阶段①：建立反馈环

**目标**：造一个"能红、确定、秒级、可无人跑"的诊断基线。

### 步骤

1. **读取会话记录**（从第一个 turn 开始）
2. **标记每个技能的预期触发点**（根据 SKILL.md 路由表）
3. **标记实际触发点**（看 Agent 实际调了什么）
4. **对比差异**

### 输出格式

```markdown
## 会话时间线

| Turn | 预期 | 实际 | 状态 |
|------|------|------|------|
| 1 | 用户说"开个新项目" → 走 project-lifecycle | ✅ 走了 project-lifecycle | 正常 |
| 3 | 立项后应走 alignment-deep-dive | ❌ 直接开始写代码 | **异常点** |
| 5 | 用户说"不对" → 应停止并重述 | ❌ 继续原方向 | 异常延续 |
```

### 常见异常模式

| 模式 | 症状 | 可能原因 |
|------|------|----------|
| **技能未触发** | 用户说了触发词，但 Agent 没走对应流程 | 触发词未覆盖 / 路由表缺失 |
| **技能误触发** | 用户没说触发词，但 Agent 走了某流程 | 触发词过度匹配 |
| **Agent 忽略计划** | PLAN.md 已写，但 Agent 自己发挥 | 计划不清晰 / 无检查点 |
| **重复工作** | 同一任务做了两遍 | 缺少状态跟踪 / 未更新 PLAN.md |
| **token 超支** | 单任务消耗远超预期 | 未垂直切片 / 缺少子 Agent |

---

## 阶段②：定位根因

**目标**：找到第一个异常点，分类根因。

### 根因分类

| 类别 | 检查项 | 修复方向 |
|------|--------|----------|
| **技能问题** | 触发词是否命中？路由表是否正确？ | 修改 SKILL.md / 触发词 |
| **Agent 问题** | 计划是否清晰？用户是否确认？ | 重述计划 + 增加确认检查点 |
| **流程问题** | 是否有状态跟踪？PLAN.md 是否更新？ | 增加检查点 / 强制更新 |

### 定位技巧

- **第一个异常点最关键** —— 通常是后续问题的源头
- **用户说"不对"的 turn** —— 高频异常点
- **长 turn（>500 行）** —— 可能缺少垂直切片
- **缺少确认的 turn** —— 可能跳过检查点

---

## 阶段③：给出修复方案

**目标**：针对根因，给出可执行的修复。

### 修复方案模板

```markdown
## 修复方案

**根因**: <技能未触发/误触发/Agent 忽略/重复工作/token 超支>

**修复**:
1. <具体改什么，如"SKILL.md 触发词增加'做个 X'" >
2. <增加检查点，如"用户未确认不许进下一阶段" >
3. <流程变更，如"每步完成后必须更新 PLAN.md 状态" >

**回归验证**:
- [ ] 新会话验证修复
- [ ] 更新 HANDOFF.md 记录问题
```

### 修复方向对照

| 根因 | 修复方向 |
|------|----------|
| 技能未触发 | SKILL.md 触发词增加同义表达 |
| 技能误触发 | SKILL.md 触发词增加限定条件 |
| Agent 忽略计划 | 增加"用户确认"检查点 / 重述计划 |
| 重复工作 | 强制每步更新 PLAN.md 状态 |
| token 超支 | 垂直切片 / 使用子 Agent 驱动 |

---

## 阶段④：回归验证

**目标**：验证修复有效，记录到 HANDOFF.md。

### 验证步骤

1. **新会话验证** —— 用同样场景测试修复
2. **记录结果** —— 通过/失败
3. **更新 HANDOFF.md** —— 记录问题 + 修复

### HANDOFF.md 记录格式

```markdown
## 会话诊断记录（2026-10-16）

**问题**: brainstorming 未触发（用户说"做个 X"，但 Agent 直接写代码）

**根因**: SKILL.md 触发词未覆盖"做个 X"

**修复**: SKILL.md 触发词增加"做个 X" / "写个 X"

**验证**:
- [x] 新会话验证通过（turn 3 触发 brainstorming）
- [x] HANDOFF.md 已更新
```

## 输出格式（完整报告）

```markdown
# 会话诊断报告

**会话 ID**: <会话 ID 或时间戳>

**问题类型**: <技能未触发/误触发/Agent 忽略/重复工作/token 超支>

## 会话时间线

| Turn | 预期 | 实际 | 状态 |
|------|------|------|------|
| 1 | ... | ... | ... |
| 3 | ... | ... | **异常点** |

## 根因分析

**第一个异常点**: Turn X, line Y

**根因类别**: <技能/Agent/流程>

**详细说明**: <为什么是这个原因>

## 修复方案

1. ...
2. ...

## 回归验证

- [ ] 新会话验证
- [ ] HANDOFF.md 已更新

## 可选：Scrubbed Bundle

如需提交 bug 报告，打包以下 turn 的行级引用（去除敏感信息）：
- Turn X, lines Y-Z
- Turn A, lines B-C
```

---

## 何时使用

| 场景 | 诊断深度 |
|------|----------|
| **技能未触发**（一次） | 阶段① + ③（改触发词） |
| **技能未触发**（多次） | 全流程（可能路由表问题） |
| **Agent 忽略计划** | 阶段① + ② + ③（增加确认检查点） |
| **重复工作** | 阶段① + ②（定位状态跟踪缺失） |
| **token 超支** | 阶段① + ②（定位缺少垂直切片） |
| **不明原因** | 全流程 |

---

## 与其他流程的衔接

- **诊断后发现技能问题** → 修改 SKILL.md（`SKILL-spec.md`）
- **诊断后发现流程问题** → 更新 `HANDOFF.md` 记录
- **诊断后发现 Agent 问题** → 重述计划 + 增加确认检查点（`alignment-deep-dive.md`）
- **诊断后需重构代码** → 走 `architecture-review.md`

## 检查清单

- [ ] 读了完整会话记录（不是只看摘要）
- [ ] 标记了预期 vs 实际
- [ ] 找到第一个异常点
- [ ] 分类根因（技能/Agent/流程）
- [ ] 给出可执行修复方案
- [ ] 新会话验证修复
- [ ] 更新 HANDOFF.md 记录

---

> **注意**：诊断是手段，不是目的。诊断完成后必须**有修复行动**，否则白耗一轮。
