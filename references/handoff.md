# 会话交接（提炼自 mattpocock 的 handoff）

> 用于任务跨会话、跨人、跨 Agent 接力时，把当前进展压缩成一份交接文档。
> 触发说法："交接 / handoff / 换人接着做 / 切会话 / 把上下文总结一下给下一个"。

## 去哪儿写

**操作系统临时目录**，不是当前工作区：`$TMPDIR` → 否则 `/tmp`；Windows 用 `%TEMP%`。

文件名建议 `handoff-<时间戳>.md`，每次运行一个新文件，避免覆盖上一场的交接。

写完告诉用户文件的**绝对路径**。

## 文档必含五段

1. **当前进展**：做到哪一步、什么状态、最后一次验证结果是什么。
2. **接下来要做**：明确的下一步动作（不是笼统方向）。
3. **建议调用的技能（suggested skills）**：点名下一个 Agent 该用哪些技能、为什么。
4. **关键决策与约束**：已经定下来的事，别让下一个 Agent 重新纠结一遍。
5. **踩过的坑**：已经排查过的方向和无效尝试，避免重复劳动。

## 三条规则

- **不要复制其他产物已有的内容。** spec、计划、ADR、issue、commit、diff 里有的一律**用路径或 URL 引用**，不要摘抄——否则交接文档会和源文件两处漂移。
- **脱敏。** API key、密码、token、个人身份信息全部去掉，写成 `<已配置，见 xxx>` 的形式。交接文档会被人翻来翻去去。
- **用户传了参数就按参数裁剪。** 如果用户说"下一场要做 X"，文档就以 X 为主线组织，而不是平铺全部历史。

## 检查清单

写完自查：

- [ ] 下一个 Agent 读完这份文档，**不需要回头翻聊天记录**就能继续？
- [ ] "接下来要做"是**具体动作**，不是"继续推进 X"这种虚话？
- [ ] 提到的事实都有路径/链接可核对？
- [ ] 敏感信息已全部脱敏？
